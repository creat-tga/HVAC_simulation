# UI/UX 问题清单（系统方案详情页）

> 审查时间：2026-04-26
> 审查环境：
> - 大屏：1822 × 850（VS Code Simple Browser 全屏）
> - 小屏：约 818 × 850（VS Code Simple Browser 默认侧栏宽度）
>
> 审查范围：`/projects/:pid/system-schemes/:sid` 三个 step（设备选型 / 控制策略 / 系统图），以及外层导航、侧边栏。
>
> 严重度：🔴 阻塞 / 🟡 重要 / 🟢 优化。

---

## 1. 全局布局 & 双重导航

| 编号 | 严重度 | 问题 |
|---|---|---|
| G-1 | 🟡 | **顶部双层 header 重复**：根 `AppHeader`（Logo + 中文 + admin）与 `ProjectWorkspaceLayout` main 内顶部 toolbar（深色 + 中文 + admin）功能重叠，用户出现两套主题/语言/账号切换器。 |
| G-2 | 🟡 | **左侧 sidebar 固定 ~380px**（"工程阶段"卡 + 三个步骤详情卡）在大屏占用 21% 宽度仅展示路由信息，与右侧内容主体的密度反差过大。 |
| G-3 | 🟢 | 左侧"工程阶段"三个步骤卡片字号偏大（描述文字 12px 但卡片 padding 24px），与右侧表单 13px / 行高 28px 的紧凑感不协调。 |
| G-4 | 🟢 | 全局背景为浅灰渐变，主内容卡片为白底 + 1px border，但子区块（设计参数 / 组合 / 冷却塔）也是白底+border，形成 "卡中卡中卡" 嵌套，缺少层次。 |

## 2. 顶部步骤条 / 工具栏（SystemSchemeDetailView 顶部）

| 编号 | 严重度 | 问题 |
|---|---|---|
| T-1 | 🔴 | **小屏（≤ ~900px）下，步骤条文字"设备选型/控制策略/系统图" 完全消失**，只剩数字圆圈，用户无法识别当前步骤。需要响应式策略：要么数字+文字垂直堆叠，要么显示 tooltip。 |
| T-2 | 🟡 | "返回方案列表 \| 方案 2（输入框） \| 步骤条 \| 保存" 全挤一行，**步骤条夹在中间**，失去视觉重心。建议步骤条独立成第二行或移到内容区顶部。 |
| T-3 | 🟡 | "保存" 按钮使用强烈的青绿渐变（`#06b6d4` 系），与 step 高亮色（紫蓝渐变）撞色，按钮主次关系不清。 |
| T-4 | 🟢 | "方案 2" 输入框无 label，纯白边框无聚焦提示，用户不易察觉这是可编辑字段。 |

## 3. 顶部能力总览卡（制冷 / 制热）

| 编号 | 严重度 | 问题 |
|---|---|---|
| C-1 | 🟡 | 制冷/制热两张卡并排，**alert "制热 装机容量小于负荷峰值" 单独占一整行**，可合并到红色制热卡内（如卡边框/底色变红 + 卡内 inline 警告）。 |
| C-2 | 🟢 | 卡内 "负荷峰值 1015.0 kW / 装机容量 17860.0 kW" 两段文字间用 "/" 分隔，间距小、字号一致，难以快速分辨"实际 vs 容量"。 |
| C-3 | 🟢 | 制冷卡用浅蓝渐变、制热卡用浅黄渐变，色彩主题统一，但 "装机容量" 数字与 "负荷峰值" 数字字号一样大，导致最重要的"负荷"信息没有被突出。 |

## 4. 子系统列表 / 折叠条

| 编号 | 严重度 | 问题 |
|---|---|---|
| S-1 | 🔴 | **小屏（818px）下，子系统折叠条右侧"· 制冷量 16800 kW"被压成竖排单字**（每个汉字独占一行）。需要 `flex-shrink: 0` + 在不够宽时改成 tooltip 或截断。 |
| S-2 | 🟡 | "#1 → 名称输入框 → 类型 tag → 折叠态信息"四元素分布零散，**name 输入框边框和折叠条容器同色** (`white on white`)，缺乏视觉提示。 |
| S-3 | 🟡 | 删除按钮 "🗑 删除" 使用纯红文字 + outline，**与右上角全局"+ 新增系统"形成对称**，但红色过抢眼，建议改为 hover 显示或灰底图标。 |
| S-4 | 🟢 | 折叠态信息 "· 制冷量 16800 kW" 前缀的 "·" 圆点视觉无意义，可删除或换为竖线分隔。 |
| S-5 | 🟢 | "共 3 个子系统 / 5" 与右侧"选择模式 / 新增系统"在同一行，左侧文字孤立，建议统一字号/对齐基线。 |
| S-6 | 🟢 | "选择模式"按钮（outline）和"新增系统"按钮（primary）紧邻，但前者图标=齿轮，后者=加号，**功能层级不清**——"选择模式"是个不常用的进阶操作，应弱化（如下拉菜单的"⋯ 更多"内）。 |

## 5. 设计参数区（DesignParamsForm）

| 编号 | 严重度 | 问题 |
|---|---|---|
| D-1 | 🟡 | **大屏 1822px 下仍固定 3 列 grid**，制冷机房系统的 7 个字段排成 3+3+1，最后一行只有 1 个字段，**右侧大面积空白**。建议 ≥1600px 宽时切到 4 列。 |
| D-2 | 🟢 | 字段 label 和输入框的间距 (~8px) 偏紧凑，与组合区/冷却塔区的 label 排版不一致。 |
| D-3 | 🟢 | 单位标记 "(°C)" "(mH₂O)" 与 label 同字号同色，不易快速扫读，建议改灰色 12px。 |

## 6. 组合区（ComboEditor）

| 编号 | 严重度 | 问题 |
|---|---|---|
| O-1 | 🟡 | **每个组合的派生数据用了多种排版**：冷机派生（系列/COP/制冷量...）是真表格灰底；冷冻水泵派生（流量/扬程/耗电量/效率）是 4 列网格 + 蓝底；冷却水泵派生同样网格但**橙底**。三种风格混用，视觉噪音大。 |
| O-2 | 🟡 | 冷却水泵派生用橙色（vs 冷冻水泵蓝色）作为系统标识颜色，但**橙色与全局 alert 警告色冲突**，用户误以为有错误。 |
| O-3 | 🟡 | "组合 #1" 标题、"厂家参数"按钮、🗑 删除 图标挤在同一行右上角，且 "厂家参数"按钮用 outline 描边，与背景同色对比度低。 |
| O-4 | 🟡 | "+ 新增组合" 按钮浮在组合区标题行最右侧，渐变青绿色，**与顶部"保存"按钮颜色重复**，违反"全页主操作只有一个"的原则。 |
| O-5 | 🟢 | 组合分组之间无明显视觉分隔（仅一条 border），10 个组合连续排列时容易混淆"哪些字段属于哪个组合"。 |
| O-6 | 🟢 | "泵机直连 / 水泵并联" 单选采用 segmented 风格，但**整页只在水泵区出现**，与其它单选/下拉风格不一致。 |
| O-7 | 🟢 | 派生表中 "冷冻侧压降 7 mH₂O" 等单位用下标 H₂O，渲染效果不稳定（不同字体/缩放下数字位置漂移）。 |

## 7. 冷却塔区（TowerGroupEditor）

| 编号 | 严重度 | 问题 |
|---|---|---|
| W-1 | 🟡 | "冷却塔" 标题与右侧 "厂家参数 / + 新增冷却塔组合" 间距太大，且按钮颜色与组合区"+ 新增组合"完全相同，**层级未区分**。 |
| W-2 | 🟡 | 派生表 "流量/耗电量/出水"（左列）和 "扬程/进水/湿球"（右列）用橙色字体 label，**与组合区冷却水泵橙色派生表重复**，进一步加深"橙色 = 冷却"的强语义，但用户其实不一定能 picked up 这层规约。 |
| W-3 | 🟢 | "冷机需求冷却流量 3465.0 m³/h" 与 "冷却塔可提供的流量 275.0 m³/h" 是关键校验信息（容量严重不足），但仅用普通灰底单元格陈述，**没有警告色或 alert**。 |
| W-4 | 🟢 | 冷却塔型号下拉框宽度（与水泵型号下拉一样占 60%）但只显示 "BAC 275-11" 短文本，浪费宽度。 |

## 8. 控制策略 step - 负荷分配区

| 编号 | 严重度 | 问题 |
|---|---|---|
| L-1 | 🔴 | **"负荷分区"列宽固定且分区数量大时（70+ 个分区），分区芯片 (`分区1`...`分区72`) 被强制 9 列网格 + 内部纵向滚动条**，用户无法快速看到全部分区，也不能 drag-and-drop 排序。 |
| L-2 | 🟡 | "系统" 列下的 tag (`制冷机房系统 1` 青色 / `2` 灰色 / `风冷模块系统 3` 橙色) 颜色无规范，看不出含义。 |
| L-3 | 🟡 | "分配方式" 列：固定比例 / 按系统优先级 单选，下方紧跟三个 % 输入框 + "合计 100.0%" 提示，**% 输入框右对齐文字 + 强制 1 位小数**，用户输入易触发 NaN/jitter。 |
| L-4 | 🟡 | 顶部"安全裕量 1.00" 输入框孤零零浮在右上角，无 label 解释含义，无单位。 |
| L-5 | 🟢 | "组数 1 [恢复默认分配]" 按钮组与"安全裕量"在不同行，但功能都是负荷分配的全局参数，**应聚合到一个工具条**。 |

## 9. 控制策略 step - 详细策略 / 加减机策略表

| 编号 | 严重度 | 问题 |
|---|---|---|
| K-1 | 🔴 | **加减机策略表 10 列表头全是 "格力 CE1200 / 1200 kW × 1"**，用户无法区分这 10 列对应哪些组合（应在表头加 "组合 #1 / 组合 #2..." 前缀，或合并相同型号的列）。 |
| K-2 | 🟡 | 表格水平滚动条出现在表格底部，但**首列"档位"和末列"操作（+ 🗑）"未冻结**，长表用户拖动时容易迷失。 |
| K-3 | 🟡 | 减机/加机负荷率(%) 列宽与其它列一样，但内容是"35 / 46.67 / 52.5..."等小数，**应右对齐**且首格档位 1 减机率为 "—"（图中显示空，不易识别）。 |
| K-4 | 🟢 | "冷量段(kW)" 列的范围用 "840 ~ 2160" 格式，~ 号在中文环境下不如 — 或 → 直观。 |
| K-5 | 🟢 | "+ 新增开机组合" 按钮与"自动生成默认开机策略"按钮并排，**前者主色后者 outline**，视觉上前者更显眼，但功能频次后者更高（一键生成）。 |

## 10. 控制策略 step - 水泵/冷却塔控制 / 水温区

| 编号 | 严重度 | 问题 |
|---|---|---|
| P-1 | 🟡 | "冷冻水泵 / 冷却水泵 / 冷却塔" 三行频率输入用 grid 排版，但 "冷却塔" 多了 m / k 两列，**冷冻水泵和冷却水泵的 m/k 列空缺却保留宽度**，造成对齐怪异。 |
| P-2 | 🟢 | "m、k 为系数，n 为制冷机开启台数" 解释文字用 12px 灰色，紧贴输入框下方，**没有"i" icon 提示**用户这是公式说明。 |
| P-3 | 🟢 | 水温区（冷冻出水/冷冻进出水温差/逼近度/冷却进出水温差）四组 input + 时间表配置，每组都是一行 label + input，**字段密度过低**，可改为 2×2 网格。 |

## 11. 子系统折叠 / 切换状态

| 编号 | 严重度 | 问题 |
|---|---|---|
| F-1 | 🟡 | 控制策略 step 的子系统折叠条（"制冷机房系统 2 / 风冷模块系统 3"）默认折叠态显示 "[恢复默认策略]" 按钮 + ">" 箭头，**没有显示该子系统已经定义了多少日程组、多少档位**等概览信息，用户无法快速判断"是否需要展开"。 |
| F-2 | 🟢 | 子系统折叠条的箭头方向（v / >）和动画与设备选型 step 的折叠条不完全一致，影响一致性。 |

## 12. 加载与反馈状态

| 编号 | 严重度 | 问题 |
|---|---|---|
| R-1 | 🟡 | "保存" 按钮无 loading 态。点击后用户不知道是否在请求中，可能反复点击。 |
| R-2 | 🟢 | 保存成功的 ElMessage Toast 与设备选型修改后的 dry-run 校验提示没有视觉区隔，**多个 toast 叠在一起难以阅读**。 |
| R-3 | 🟢 | 子系统首次展开的骨架屏 (`el-skeleton`) 仅持续 2 帧，部分用户在快网络下可能根本看不到，但慢机器上又会一闪而过；考虑改为 transition fade-in。 |
| R-4 | 🟢 | 切换到"系统图" step 时无任何 loading（图表生成可能要几百 ms），用户感觉卡顿。 |

## 13. 风格统一性 / 设计语言

| 编号 | 严重度 | 问题 |
|---|---|---|
| U-1 | 🟡 | 整页**至少 5 种主色调**：青 (`#06b6d4` 步骤激活)、紫蓝渐变 (顶部条/侧边栏激活)、绿 (✓ 完成 step)、橙 (alert + 冷却派生)、红 (删除)。**缺乏统一色板**。 |
| U-2 | 🟡 | 按钮分 5 类：primary 渐变、primary 纯色、outline、文字按钮 (link)、icon-only。**5 种风格在同一区域出现**（如"+ 新增组合"是渐变青、"厂家参数"是 outline、"删除"是红文字），缺主次。 |
| U-3 | 🟢 | 字号系统：12 / 13 / 14 / 16 / 18 共 5 档，但实际命中无明确语义映射（同一层级标题字号会变）。 |
| U-4 | 🟢 | 圆角：4px / 6px / 8px / 12px 混用（input 4、卡片 6、按钮 8、step 圆圈 12）。 |
| U-5 | 🟢 | 图标库：同时使用 `@element-plus/icons-vue`、`lucide-vue-next`、emoji（🌐 中文 / 👤 admin），**风格不统一**。 |

## 修复建议优先级

按"工时 / 收益"排序，建议三个迭代：

### 迭代 1（修阻塞 + 一次设计语言对齐，1 个工作日）
- 🔴 T-1：步骤条小屏文字消失 → 媒体查询 + tooltip
- 🔴 S-1：折叠条信息文字竖排 → flex 布局调整 + truncate
- 🔴 L-1：负荷分区芯片大量时滚动 → 改为可折叠 + 搜索
- 🔴 K-1：加减机策略表头同名 → 加 "组合 #N" 前缀
- 🟡 U-1 + U-2：定义色板（主色 1 + 辅色 2）+ 按钮 3 级（primary/secondary/text），全页替换

### 迭代 2（顶部 + 卡片层级 + 派生数据统一，1 个工作日）
- 🟡 G-1 + G-2：合并双 header，sidebar 可折叠收窄
- 🟡 T-2 + T-3：步骤条独立成行，"保存"按钮配色与步骤条配色区分
- 🟡 C-1：合并 alert 到制热卡内
- 🟡 O-1 + O-2 + W-2：派生数据表统一为同一灰底样式，去掉蓝/橙双色
- 🟡 D-1：设计参数大屏切 4 列

### 迭代 3（细节打磨，0.5 个工作日）
- 🟡 S-2 ~ S-6：子系统折叠条排版
- 🟡 K-2 + K-3：策略表首末列冻结 + 数字右对齐
- 🟡 R-1：保存按钮 loading 态
- 🟢 其余 🟢 项酌情打磨
